## ส่วนที่ 1: ตรวจสอบซ้ำให้ครบ — งานที่เคยทำกับโมเดลรุ่นก่อนหน้า ยังไม่เคยเช็คกับโมเดลล่าสุด

**ที่มา**: พบว่า backtest ฤดูฝุ่น, การเทียบ ensemble, และ ablation ทีละ feature (ตารางในเอกสารเดิม ส่วน 3.1-3.2) ทั้งหมดรันบนโมเดล candidate ที่ตอนนั้นยังไม่ใช่รุ่นล่าสุดจริง — เพราะระหว่างนั้นมีการปรับ spatial-lag feature จาก k=3 เป็น k=1 (จังหวัดเพื่อนบ้านที่ใช้เฉลี่ยค่า PM2.5) ทำให้ตัวเลขในเอกสารเดิมล้าสมัยไปทันที

**วิธีทำ**: รันชุดทดสอบเดิมซ้ำทั้งหมดบนโมเดล k=1 (MAE ดีขึ้นกว่าเดิม k=3 อยู่แล้ว 1.2-1.9% จากการ retrain k=1)

**หลักฐาน**:

| การทดสอบ | ผลบนโมเดล k=3 เดิม | ผลบนโมเดล k=1 ล่าสุด |
|---|---|---|
| MAE ปกติ / ฤดูฝุ่น (LGB/XGB) | 1.96/3.66 — 2.00/3.79 | **1.79/3.48 — 1.82/3.62** (ดีขึ้นทุกจุด) |
| Coverage ที่ >p90 | 85.5%/81.9% | 84.9%/80.8% (นิ่ง/แย่ลงนิดหน่อย แม้ MAE ดีขึ้น) |
| Ensemble vs Routing | ensemble แพ้ `lgb_only` ทุก config | `weighted_avg` ชนะ `lgb_only` เล็กน้อย (-0.11%, เกือบเสมอ) |
| Individual ablation (feature เดี่ยว) | รันบน dataset k=3 (ไม่ตรงรุ่นจริง) | รันซ้ำบน dataset k=1 จริง — อันดับความสำคัญเหมือนเดิมทุกจุด |

**สรุป**: ยืนยันว่าข้อสรุปเดิมส่วนใหญ่ยัง valid กับโมเดล k=1 (multicollinearity, ensemble ไม่ช่วย) แต่**ตัวเลข coverage ที่ >p90 ไม่ดีขึ้นตามที่คาด แม้ MAE ดีขึ้นชัดเจน** — เป็นหลักฐานสำคัญว่า conformal calibration เป็นกลไกที่แยกขาดจาก feature engineering โดยสิ้นเชิง (ไปต่อ ส่วนที่ 3)

## ส่วนที่ 2: หาสาเหตุที่แท้จริงของ finding เดิม — ทำไมตัด time_cyclical แล้ว MAE ดีขึ้น

**ที่มา**: เอกสารเดิม (ตาราง 3.1-ก) รายงานว่าตัด hour/month/dayofweek ออกแล้ว MAE ดีขึ้น (ขัดสมมติฐานตั้งต้น) แต่ตอนนั้นมีแค่**ข้อสังเกต** ไม่มี**คำอธิบายที่ตรวจสอบแล้ว**

**วิธีทำ**: (1) correlation matrix ระหว่าง time_cyclical กับกลุ่ม pm25_lag/rolling (2) ทดลองใส่กลับทีละกลุ่มย่อย (hour cyclical / month cyclical / dayofweek) แทนที่จะมองเป็นก้อนเดียว

**หลักฐาน**:

| Sub-feature | Correlation กับกลุ่ม lag/rolling | ผลตอนใส่กลับ (delta MAE) |
|---|---|---|
| `month_sin`/`month_cos` | **0.52-0.57** (สูงมาก) | **+1.44%/+1.81%** (แย่ลงชัดเจนสุด) |
| `hour_sin`/`hour_cos` | ~0.01 (แทบไม่มี) | -0.34%/+0.01% (แทบไม่มีผล) |
| `dayofweek` | ~0.01-0.02 | +0.35%/+0.46% (แย่ลงเล็กน้อย) |

**สรุป**: สมมติฐานเดิม ("ซ้ำซ้อนกับ lag/rolling") **ถูกแค่บางส่วน** — จริงเฉพาะ `month_sin/cos` (multicollinearity ชัดเจน, ตรงกับ finding เรื่องความชื้น/ฤดูกาลในเอกสารเดิม ส่วน 2.2) ส่วน `hour_sin/cos` ไม่ redundant กับอะไรเลย แค่ไม่มีข้อมูลใหม่ให้เพิ่ม ✅ ปิดประเด็นนี้ครบแล้ว

## ส่วนที่ 3: Coverage ช่วงฝุ่นวิกฤต — ทดลองเพิ่มเติม 4 วิธี (ต่อจาก "⚠️ ยังเปิดอยู่")

**ที่มา**: เอกสารเดิมทิ้งท้ายว่า group-conditional calibration ช่วย XGBoost บางส่วน (81.4%→84.9%) แต่ LightGBM แทบไม่ตอบสนอง — ยังไม่ถึงเป้า 90% ทดลองต่อ 4 มุม

| # | วิธี | ผล (coverage ที่ >p90, LGB/XGB) | สรุป |
|---|---|---|---|
| 1 | Group-conditional ซ้ำบนโมเดล k=1 (severity-only) | 84.9%→**86.2%** / 80.8%→**85.3%** | ✅ ดีขึ้นกว่าตอนทำบนโมเดล k=3 เดิมด้วยซ้ำ — **ดีที่สุดในบรรดา 4 วิธี** |
| 2 | จัดกลุ่มตามจังหวัด+severity (relative percentile ต่อจังหวัด) | 85.3%→81.9% / 79.5%(baseline คนละโมเดล)→79.6% | ❌ แย่กว่าเดิม (ขนาดกลุ่มเล็กเกินไป + นิยาม severity ไม่ตรงกับตอนวัดผล) |
| 3 | แก้ปัญหานิยามจากข้อ 2 (ใช้ threshold สัมบูรณ์ร่วม) | ดีขึ้นกว่าข้อ 2 แต่ยังแพ้ข้อ 1 | ❌ ยังไม่คุ้ม — ขนาด calib ปัจจุบันเล็กเกินไปสำหรับแบ่ง 2 มิติพร้อมกัน |
| 4 | จัดกลุ่มตาม pm25_std (ความผันผวน) ของจังหวัด | แทบไม่ต่างจาก single q_hat, ช่วย zero-shot บางจังหวัดแต่ทำให้บางจังหวัดแย่ลง | ❌ ไม่คงเส้นคงวา |

**สรุป**: ทดสอบครบทุกแนวทางที่เป็นไปได้ในทางปฏิบัติแล้ว — **`group-conditional calibration แบบ severity-only (วิธีที่ 1) ยังเป็นคำตอบที่ดีที่สุด** ยังไม่ถึงเป้า 90% เต็มที่ แต่ใกล้ที่สุดเท่าที่เคยทำได้ (ต่อยอดอีกครั้งใน ส่วนที่ 5 หลังเพิ่ม feature ใหม่)

## ส่วนที่ 4: Zero-shot generalization — เพิ่มกำลังทางสถิติ และเช็คกับข้อมูลจริงเป็นครั้งแรก

**ที่มา**: เอกสารเดิม (ส่วน 1.4-ก) ทดสอบด้วยจังหวัด held-out แค่ 3 จังหวัด (n=3 จุดข้อมูล) สรุปทางสถิติไม่ได้ และไม่เคยเช็คกับ**จังหวัด zero-shot จริง**ที่แอปเสิร์ฟอยู่เลยสักครั้ง

**วิธีทำ 1 — เพิ่ม n จาก 3 เป็น 17**: Leave-one-province-out (LOPO) ข้ามทั้ง 17 จังหวัดที่เทรนได้จริง

**หลักฐาน**: correlation(ระยะทาง, MAE) = **+0.28 ถึง +0.30** (ทิศทางตรงสมมติฐานแล้ว ต่างจาก n=3 เดิมที่ขัดทิศทาง) แต่ p-value = 0.24-0.29 ยังไม่ถึงเกณฑ์นัยสำคัญ — ทดสอบตัวแปรอื่นเพิ่มเติมพบว่า **`pm25_std` (ความผันผวนของจังหวัดเอง) อธิบาย MAE ได้ดีกว่าระยะทางมาก: r=0.85-0.87, p<0.0001 (significant จริง)**

**วิธีทำ 2 — เช็คกับ ground truth จริง**: พบว่า dataset ที่ใช้เทรนมี PM2.5 จริงของ 3 จังหวัด zero-shot (นครพนม/ร้อยเอ็ด/มหาสารคาม) อยู่แล้ว (แค่ไม่ถูกใช้เทรน) — ไม่ต้องดึงข้อมูลใหม่

**หลักฐาน**:

| จังหวัด | ระยะทางจากจังหวัดเทรนใกล้สุด | Coverage (LGB/XGB) |
|---|---|---|
| มหาสารคาม | 37 กม. | 80.8% / 83.0% |
| ร้อยเอ็ด | 45 กม. | 87.1% / 85.9% |
| **นครพนม** | **74 กม. (ไกลสุด)** | **74.1% / 72.7% (แย่สุดชัดเจน)** |

**สรุป**: coverage ของทั้ง 3 จังหวัด zero-shot จริงต่ำกว่าจังหวัดเทรน (~88-89%) อย่างชัดเจนทุกจังหวัด — สมเหตุสมผลเชิงทฤษฎี (conformal prediction รับประกัน coverage ได้เฉพาะข้อมูลที่มาจาก distribution เดียวกับ calibration set) นครพนม (ไกลสุด + ผันผวนสูงสุด) แย่สุดตรงกับทั้ง 2 สมมติฐาน — **เป็นข้อจำกัดที่ควรระบุให้ชัดเจนถ้าจะ deploy จริง ไม่ใช่แค่ดู MAE เฉลี่ยรวมที่ดูดี**

## ส่วนที่ 5: ทดลอง Feature ใหม่ — ข้อมูลจุดความร้อนจากดาวเทียม (NASA FIRMS)

**ที่มา**: จุดอ่อนที่ยังไม่แก้ตกทั้งหมด (ส่วนที่ 3-4) มีจุดร่วมกันคือ**ไม่มี feature ไหนสังเกตสาเหตุจริงของฝุ่นวิกฤต (การเผาไร่/ป่า) โดยตรงเลย** — ทุก feature เดิมเป็นแค่ผลลัพธ์ทางอ้อม (สภาพอากาศ/ประวัติฝุ่น/พิกัด) จึงทดลอง NASA FIRMS (ข้อมูลจุดความร้อนจากดาวเทียม VIIRS ให้บริการฟรี)

**วิธีทำ**: ดึงข้อมูลย้อนหลังเต็มช่วงเทรน (2024-2026, 476,426 จุด) คำนวณเป็น feature "จำนวนจุดความร้อนในรัศมี 100 กม. ย้อนหลัง 24 ชม." ต่อจังหวัด/ชั่วโมง (ทดลองปรับ radius/window หลายค่าแล้ว ค่านี้ดีที่สุด) validate แบบย่อก่อน retrain เต็ม ตามธรรมเนียมเดิม (เทียบ spatial-lag feature ส่วน 1.4-ข)

**หลักฐานขั้น validate**:
- Correlation ดิบกับ PM2.5 = **0.504** (แรงกว่าทุก feature ที่เคย validate ในโปรเจกต์นี้)
- **นครพนม/บึงกาฬ (2 จังหวัดริมแม่น้ำโขงที่ ส่วนที่ 4 หาสาเหตุความผันผวนสูงไม่เจอ) มีค่าเฉลี่ยจุดความร้อนสูงสุดในกลุ่ม 20 จังหวัด** — ให้หลักฐานเชิงประจักษ์ตรงๆ เป็นครั้งแรกว่าน่าจะเกี่ยวกับกิจกรรมเผาไร่ข้ามพรมแดน ไม่ใช่ปัจจัยลึกลับ

**หลักฐานขั้น retrain เต็ม + ตรวจสอบซ้ำครบ 4 มุม (เหมือนที่ทำกับโมเดล k=1 ทุกจุด)**:

| มุมที่ตรวจ | ผล |
|---|---|
| MAE ที่ severity สูงสุด (>p90) | ดีขึ้นทั้ง 2 โมเดล (**-1.4%** ทั้งคู่) |
| MAE รวม/ช่วงปกติ | ก้ำกึ่ง (LGB ดีขึ้นนิดหน่อย, XGB แย่ลงนิดหน่อย) — ไม่ใช่ feature ที่ "แรง" แบบ spatial-lag ในภาพรวม |
| Coverage ที่ >p90 (single q_hat) | LGB ดีขึ้น (+0.4pp) **XGB แย่ลง (-1.3pp)** |
| **Coverage ที่ >p90 (รวมกับ calibration ที่ดีที่สุดจากส่วนที่ 3)** | **LGB 87.1%, XGB 85.1% — coverage สูงสุดที่เคยทำได้ในทั้งโปรเจกต์** |
| **จังหวัด zero-shot จริง (นครพนม)** | **MAE ดีขึ้น -2.3%, coverage ดีขึ้น +1.4 ถึง +1.8pp — ยืนยันสมมติฐานในทางปฏิบัติจริง** |
| Ensemble vs Routing / Individual ablation | ผลเหมือนเดิมทุกจุด ไม่มีอะไรขัดแย้งใหม่ |

**สรุป**: feature นี้**ไม่ใช่ตัวที่ทำให้ MAE รวมดีขึ้นแบบก้าวกระโดด** แต่**ตอบโจทย์ตรงจุดที่ยังแก้ไม่ได้มาตลอด** — ช่วยความแม่นยำช่วงวิกฤตชัดเจน และช่วยจังหวัด zero-shot ที่มีปัญหาหนักสุด (นครพนม) ได้จริงทั้ง MAE และ coverage เมื่อใช้ร่วมกับ calibration ที่เหมาะสม ได้ coverage ดีที่สุดในทั้งโปรเจกต์ — **ยังไม่ deploy เข้า `app.py`** (ต้องออกแบบการดึงข้อมูล FIRMS แบบ live ก่อน เช่นเดียวกับ spatial-lag ที่ยังรอออกแบบ live-fetch จังหวัดเพื่อนบ้านอยู่)
