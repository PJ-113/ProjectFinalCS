## ส่วนที่ 1: การวิเคราะห์ความสัมพันธ์เชิงพื้นที่ (Spatial Correlation)

### 1.1 ความสัมพันธ์ข้ามจุดวัด (ไม่มองจุดเดียว)

**วิธี**: คำนวณ Pearson correlation ของ PM2.5 รายชั่วโมงระหว่างทุกคู่จังหวัด (190 คู่จาก 20 จังหวัด) เทียบกับระยะทางจริง (haversine)

**หลักฐาน**: correlation(ระยะทาง, ความสัมพันธ์) = **−0.644**

| คู่จังหวัด | ระยะทาง | Correlation |
|---|---|---|
| กาฬสินธุ์ – มหาสารคาม | 37 กม. | 0.94 |
| บึงกาฬ – นครราชสีมา | 411 กม. | 0.46 |

**สรุป**: จังหวัดใกล้กันมี PM2.5 สัมพันธ์กันสูงกว่าจังหวัดไกลชัดเจน ✅

### 1.2 เขตเมือง vs เขตนอกเมือง

**วิธี**: ใช้ OpenStreetMap Overpass API วัดที่พิกัดสถานีจริง — ลองครั้งแรกนับจำนวนอาคาร ได้ผลขัดความจริง (มหาสารคามสูงกว่าโคราช/ขอนแก่นซึ่งเป็นเมืองใหญ่กว่า) ตรวจสอบพบว่าอาคาร 100% ในมหาสารคามมี tag `building=roof` เหมือนกันหมด (0.05% มี tag รายละเอียด) = สัญญาณ **OSM bulk-import artifact** ไม่ใช่ข้อมูลจริง แก้โดยเปลี่ยนไปนับ **amenity/shop POI** แทน

**หลักฐาน** (หลังแก้ไข): ลำดับสมเหตุสมผล — ขอนแก่น(1,434) > โคราช(852) > อุดรธานี(812) > อุบลราชธานี(643) ตรงกับ 4 เมืองเศรษฐกิจหลักอีสานจริง

| Metric | Correlation | ผล |
|---|---|---|
| ระดับฝุ่นเฉลี่ย | **+0.32** | เขตเมืองฝุ่นเฉลี่ยสูงกว่าจริง |
| ความผันผวน | −0.11 | ไม่มีผล |
| ความไม่ต่อเนื่องรายชั่วโมง | +0.01 | ไม่มีผล |

**ทดสอบเป็น model feature**: MAE เปลี่ยนแค่ 0.12%/−0.27% (noise) → ไม่คุ้ม retrain (ซ้ำซ้อนกับ lat/lon ที่มีอยู่แล้ว) ✅ ตรวจสอบครบ ไม่ใช่ข้ามประเด็น

### 1.3 ภูมิประเทศ (อีสานที่สูง vs ภาคเหนือหุบเขา)

**วิธี**: ดึง elevation จาก Open-Meteo (Copernicus DEM) ครบ 20 จังหวัด

**หลักฐาน**: elevation อีสานแคบมาก (123–237ม.) correlation กับ volatility อ่อน/ขัดที่คาด (r=−0.12 ถึง −0.32) เพิ่มเป็น feature แล้ว MAE แทบไม่เปลี่ยน (−0.11%/−0.20%)

**สรุป**: ตรวจสอบแล้ว ไม่พบผลนัยสำคัญภายในขอบเขตอีสาน (ไม่มีข้อมูลภาคเหนือเทียบข้ามภาคได้) ✅

### 1.4 ทดสอบว่าโมเดลเรียนรู้ pattern เชิงพื้นที่จริง

**วิธี**: (ก) เทียบ zero-shot MAE กับระยะทาง (ข) เพิ่ม feature ใหม่ (ค่าเฉลี่ย PM2.5 ของ 3 จังหวัดใกล้สุด) แล้ว validate ก่อน retrain

**หลักฐาน**:
- (ก) n=3 จุดน้อยเกินสรุป (correlation −0.31 ขัดสมมติฐานด้วย)
- (ข) **ยืนยันชัดเจน**: validate ได้ −4.1%/−4.3%, retrain เต็มรูปแบบได้ −4.0%/−3.7% → **นำเข้าโมเดลจริงแล้ว** ✅ (และเป็น feature เดี่ยวที่สำคัญที่สุดในโมเดล — ดูส่วน 3.1)

## ส่วนที่ 2: การเพิ่มปัจจัยทางอุตุนิยมวิทยา

### 2.1 ทิศทางลม ปริมาณฝน ความกดอากาศ

**วิธี**: ตั้งสมมติฐานทิศทางล่วงหน้า ตรวจด้วย SHAP values ที่ 3 horizon × 2 โมเดล

| ปัจจัย | สมมติฐาน | พบจริง |
|---|---|---|
| ความกดอากาศ | สูง→ฝุ่นมาก | +0.23 ถึง +0.90 ✅ |
| ความเร็วลม | แรง→ฝุ่นน้อย | −0.74 ถึง −0.79 ✅ |
| ปริมาณฝน | มาก→ฝุ่นน้อย | −0.28 ถึง −0.51 ✅ |

**สรุป**: ตรงสมมติฐานครบ 18/18 จุดตรวจ ✅

### 2.2 ความชื้น/น้ำค้างหน้าหนาว

**หลักฐาน**: correlation −0.79 ถึง −0.95 (แรงมาก) **แต่ตรงข้ามสมมติฐานเดิม** (คาด hygroscopic growth ทำให้เพิ่ม) และไม่ต่างกันหน้าหนาว vs นอกฤดู (เช่น −0.948 vs −0.955)

**คำอธิบาย**: ความชื้นเป็นตัวแทนฤดูแล้ง/ฝนมากกว่ากลไก hygroscopic — ฤดูแล้ง(ชื้นต่ำ)=เผาไร่=ฝุ่นสูง, ฤดูฝน(ชื้นสูง)=ฝนชะล้างฝุ่น กลไกนี้แรงกว่าจนกลบ hygroscopic ✅

## ส่วนที่ 3: การออกแบบการทดลองและการวัดความแม่นยำ (Backtesting)

### 3.1 Ablation study — ทั้งระดับกลุ่มและระดับ feature เดี่ยว

**(ก) ระดับกลุ่ม** — ตั้งสมมติฐานผลกระทบ feature แต่ละกลุ่ม แล้วตัดออกทีละกลุ่มทดสอบ

| กลุ่ม feature | LightGBM | XGBoost |
|---|---|---|
| pm25 lag/rolling (9 ตัว) | **+9.1%** | **+8.0%** |
| สภาพอากาศ (4 ตัว) | +1.3% | +1.7% |
| ทิศลม/ความกดอากาศ (3 ตัว) | +0.5% | +0.1% |
| lat/lon (2 ตัว) | +1.0% | −0.3% |
| เวลาเชิงวงกลม (ชม./เดือน) | **−1.7%** | **−2.5%** (ขัดสมมติฐาน — ตัดออกจริง) |

**(ข) ระดับ feature เดี่ยว** (ตอบ feedback "ทดสอบทีละตัวแปร" ตรงตัวอักษร) — leave-one-out ทีละตัวครบ 19 ตัวปัจจุบันของโมเดล

| Feature | กลุ่มที่สัมพันธ์กัน* | ΔMAE LightGBM | ΔMAE XGBoost |
|---|---|---|---|
| `pm25_neighbor_avg` | — (อิสระ) | **+4.20%** | **+3.01%** |
| `pm25_lag_24` | pm25_lag_rolling* | +0.90% | −0.34% |
| `lon` | lat_lon_pair* | +0.79% | −0.91% |
| `wind_dir_sin` | wind_dir_pair* | +0.66% | −0.48% |
| `pm25_lag_6` | pm25_lag_rolling* | +0.66% | −0.59% |
| `wind_speed` | — | +0.58% | +0.10% |
| `pm25_roll_std_6` | pm25_lag_rolling* | +0.57% | +0.27% |
| `pm25_lag_1` | pm25_lag_rolling* | +0.55% | +0.24% |
| `temp` | — | +0.46% | +0.28% |
| `humidity` | — | +0.43% | +0.15% |
| `precipitation` | — | +0.37% | +0.02% |
| `pm25_lag_3` | pm25_lag_rolling* | +0.29% | +0.18% |
| `wind_dir_cos` | wind_dir_pair* | +0.24% | −0.69% |
| `lat` | lat_lon_pair* | +0.22% | −1.05% |
| `pm25_lag_12` | pm25_lag_rolling* | +0.19% | −0.08% |
| `pm25_roll_mean_6` | pm25_lag_rolling* | +0.10% | −0.46% |
| `pm25_roll_std_24` | pm25_lag_rolling* | +0.01% | −0.86% |
| `pressure` | — | −0.11% | −0.82% |
| `pm25_roll_mean_24` | pm25_lag_rolling* | −0.17% | −0.02% |

*(ตารางเรียงตาม ΔMAE LightGBM มากไปน้อย, baseline MAE: LGB=2.644, XGB=2.759)*

**\*หมายเหตุสำคัญ — multicollinearity**: 3 กลุ่มที่ทำเครื่องหมาย (`pm25_lag_rolling` 9 ตัว, `wind_dir_pair` 2 ตัว, `lat_lon_pair` 2 ตัว) มีความสัมพันธ์กันสูงโดยธรรมชาติของการออกแบบ feature — ตัดออกทีละตัวดูเหมือนไม่สำคัญ (ตัวที่เหลือในกลุ่มชดเชยกันได้) แต่ตัดออก**ทั้งกลุ่มพร้อมกัน**ถึงเห็นผลจริงตามตาราง (ก)

พิสูจน์เชิงประจักษ์: กลุ่ม `pm25_lag_rolling` ตัดทีละตัวเฉลี่ยแค่ **+0.34%** (LGB) / **−0.19%** (XGB) แต่ตัดทั้ง 9 ตัวพร้อมกัน **+9.1%** (LGB) / **+8.0%** (XGB) — ต่างกันประมาณ 27 เท่า ยืนยัน multicollinearity hypothesis ด้วยตัวเลขจริง ไม่ใช่แค่การอนุมาน

**`pm25_neighbor_avg` โดดเด่นที่สุด** เพราะไม่มี feature อื่นในโมเดลซ้ำข้อมูลด้วย จึงรับผลกระทบเต็มๆตอนถูกตัดออกคนเดียว — เป็น**feature เดี่ยวที่สำคัญที่สุดในโมเดลทั้งหมด**

**Action**: ตัด time_cyclical ออกจากโมเดลจริงตามผลทดสอบ (ก) ✅

### 3.2 Backtest ช่วงฝุ่นสูง (ก.พ.–เม.ย.) — ทำกับโมเดลล่าสุดแล้ว

| | ช่วงปกติ | ฤดูฝุ่น | ต่างกัน |
|---|---|---|---|
| LightGBM | 1.86 | 3.45 | +85.1% |
| XGBoost | 1.90 | 3.61 | +90.2% |
| t+24 (LGB) | 3.16 | 6.03 | เกือบเท่าตัว |

**พบเพิ่ม**: Coverage ช่วงความเชื่อมั่นตกช่วงฝุ่นวิกฤต (>p90): LGB 85.0%, XGB 81.4% (เป้า 90%)

### 3.3 แก้ปัญหา Coverage

**ผล**: group-conditional conformal calibration — XGBoost ดีขึ้น 81.4%→84.9% (+3.5pp) แต่ LightGBM แทบไม่ตอบสนอง — ข้อจำกัดเชิงโครงสร้าง ⚠️ **ยังเปิดอยู่**

### 3.4 ค่า Accuracy

**สูตร**: Accuracy = 100% − MAPE% (มาตรฐานงาน forecasting เพราะเป็น regression ไม่มี accuracy แบบทายถูก/ผิด)

| | LightGBM | XGBoost |
|---|---|---|
| Accuracy รวม | **88.20%** | **87.84%** |
| Accuracy t+1 | 98.76% | 98.75% |
| Accuracy t+24 | 79.61% | 78.73% |

**หมายเหตุ**: Accuracy ฤดูฝุ่นดูสูงกว่าปกติเล็กน้อย (88.5% vs 88.2%) สวนทาง MAE ที่แย่กว่า — เพราะ MAPE วัดเป็น% ของค่าฐานที่สูงกว่าในฤดูฝุ่น แนะนำรายงานคู่กันทั้ง MAE และ Accuracy
