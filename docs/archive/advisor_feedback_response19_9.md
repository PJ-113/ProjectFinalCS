# สรุปงานเพิ่มเติมรอบที่ 3: ปรับปรุงตัวโมเดลเอง (hyperparameter) + ทดลอง feature ใหม่ + ตรวจสอบครบทุกมุม

**เอกสารนี้จัดทำสำหรับ**: อาจารย์ที่ปรึกษาโครงงาน
**วันที่**: 2026-09-19
**ขอบเขต**: ต่อจากเอกสาร `advisor_feedback_response18_9.md` (18 ก.ย.) ซึ่งทดลองแต่ feature และ calibration — รอบนี้ (1) ปรับปรุง**ตัวโมเดลเอง** (hyperparameter) ที่ยังไม่เคยแตะเลยตลอดโครงงาน (2) ทดลอง feature ใหม่ 12 ตัว (3) ทดลองแก้จุดอ่อนช่วงฝุ่นสูงด้วยการถ่วงน้ำหนักข้อมูล (4) retrain โมเดลรุ่นใหม่และทดสอบซ้ำครบชุดเดียวกับรุ่นก่อน (5) ทดลองแก้ coverage เพิ่มเติมอีก 2 วิธี

**ข้อตกลงวิธีวัดผลรอบนี้ (เข้มงวดกว่ารอบก่อน)**: เนื่องจากรอบนี้ลองหลายสิบตัวเลือก จึง**เลือกทุกอย่างบนชุด calibration เท่านั้น** ไม่แตะชุดทดสอบ (test) จนถึงขั้นยืนยันผลรวมครั้งเดียว — เพื่อกันการ "เลือกตัวที่บังเอิญดีบน test" (overfitting จากการลองหลายครั้ง)

## ส่วนที่ 1: ปรับ hyperparameter ของโมเดล — ช่องว่างที่ยังไม่เคยแตะ

**ที่มา**: ตรวจโค้ดพบว่าตลอดโครงงาน LightGBM/XGBoost ใช้ค่าเริ่มต้นของไลบรารีมาตลอด (กำหนดเพียงจำนวนต้นไม้ 300 และ bagging 0.8) — ทดลองแต่ feature กับ calibration ไม่เคยจูนตัวโมเดลเอง

**วิธีทำ**: สุ่มค้นหา (random search) 20 ชุดค่าต่อโมเดล ครอบคลุม learning rate, ความซับซ้อนของต้นไม้, ขนาดใบขั้นต่ำ, regularization, จำนวนต้นไม้ — เทรนบน train วัดบน calibration แล้วยืนยันชุดที่ดีที่สุด 3 อันดับบน 5 horizon

**หลักฐาน (MAE บน calibration เทียบค่าเริ่มต้น)**:

| โมเดล | ชุดค่าที่ดีที่สุด | MAE รวม | ช่วงฤดูฝุ่น | ช่วงฝุ่นวิกฤต (>p90) |
|---|---|---|---|---|
| LightGBM | learning rate 0.05, ใบ 63, ขนาดใบขั้นต่ำ 50, 400 ต้น | -0.84% | -1.46% | -0.72% |
| XGBoost | learning rate 0.03, ความลึก 8, min child weight 20, 800 ต้น | **-3.88%** | **-3.09%** | **-3.11%** |

**สรุป**: XGBoost ได้ประโยชน์มาก เพราะค่าเริ่มต้น (learning rate 0.3) ก้าวร้าวเกินไปสำหรับข้อมูลนี้ ส่วน LightGBM ค่าเริ่มต้นดีอยู่แล้ว ได้เพียงเล็กน้อย — ผลคือช่องว่างระหว่างสองโมเดลที่เคยเห็น (LightGBM ชนะ XGBoost ตลอด) **หายไป** ✅

## ส่วนที่ 2: ทดลอง feature ใหม่ 12 ตัว — ผ่านเกณฑ์แค่ 1 ตัว แต่ผลชัดเจน

**ที่มา**: ปรับปรุง 2 feature ที่แรงที่สุดเดิม (จุดความร้อน FIRMS และ spatial-lag) ให้ละเอียดขึ้น และทดสอบตัวแปรสภาพอากาศเพิ่มที่ยังไม่เคยใช้

**วิธีทำ**: เพิ่มทีละ 1 feature เข้าชุดเดิม (baseline ใช้ hyperparameter ที่จูนแล้วจากส่วนที่ 1) วัด MAE 4 มุม (รวม / ฤดูฝุ่น / ช่วงฝุ่นวิกฤต) บน calibration

| กลุ่ม | feature ที่ทดสอบ | ผล |
|---|---|---|
| จุดความร้อน (ปรับปรุง) | ผลรวมความรุนแรงไฟ (FRP), จำนวน/FRP ของจุดไฟ**เหนือลม** | ❌ ไม่ช่วย (+0.0% ถึง +0.3%) — จำนวนจุดแบบเดิมจับสัญญาณได้พอแล้ว |
| Spatial-lag (ปรับปรุง) | ค่าเฉลี่ยเพื่อนบ้านถ่วงตามทิศลม, ค่าสูงสุดของเพื่อนบ้าน | ❌ แย่ลงหรือเท่าเดิม |
| **Spatial-lag (แนวโน้ม)** | **`nb_trend`: แนวโน้ม PM2.5 ของจังหวัดข้างเคียงใน N ชั่วโมงที่ผ่านมา** | ✅ **MAE รวม -2.2% ถึง -2.9%** ทั้งสองโมเดล |
| ฝน/ความแห้งแล้ง | จำนวนชั่วโมงหลังฝนล่าสุด, ฝนสะสม 24/72 ชม. | ❌ ไม่ช่วย (ฝนสะสม 72 ชม. ดีขึ้นเล็กน้อยแต่ไม่เพิ่มเมื่อรวมกับ nb_trend) |
| สภาพอากาศใหม่ | ความสูงชั้นผสมอากาศ (boundary layer height), รังสีดวงอาทิตย์, เมฆปกคลุม | ❌ ชั้นผสมอากาศ MAE รวมดีขึ้นเล็กน้อยแต่**แย่ลง 2-3% ในฤดูฝุ่นและช่วงวิกฤต** (ตรงจุดที่สำคัญที่สุด) จึงตัดทิ้ง |

**ทำไม `nb_trend` ได้ผล**: เดิม spatial-lag บอกแค่ "ตอนนี้จังหวัดข้างเคียงฝุ่นเท่าไร" ส่วน `nb_trend` บอก "จังหวัดข้างเคียงกำลังเพิ่มหรือลด" ซึ่งเป็นสัญญาณของกลุ่มฝุ่นที่กำลังเคลื่อนเข้ามาล่วงหน้า (ใช้เฉพาะข้อมูลก่อนเวลาที่พยากรณ์ ไม่มีการรั่วของอนาคต) ทดสอบหน้าต่าง 1/3/6/12 ชม. ให้ผลใกล้เคียงกันทั้งหมด (ต่างกันในระดับ noise) จึงเลือก 12 ชม. ที่ดีที่สุดเล็กน้อยทั้งสองโมเดล

**หมายเหตุด้านข้อมูล**: ข้อมูลชั้นผสมอากาศของปี 2024 ขาดหายประมาณครึ่งหนึ่งในแหล่งข้อมูลย้อนหลัง — เป็นอีกเหตุผลที่ตัดทิ้งได้โดยไม่เสียดาย

## ส่วนที่ 3: ถ่วงน้ำหนักข้อมูลฝุ่นสูง — ทดลองแล้วไม่คุ้ม

**ที่มา**: โมเดลรุ่นแรก (ขอนแก่นจังหวัดเดียว) เคยแก้อคติช่วงฝุ่นสูงด้วยการถ่วงน้ำหนัก แต่โมเดลรวมทุกจังหวัดยังไม่เคยลอง และจุดอ่อนหลักคือ MAE ช่วงฝุ่นวิกฤต (~5.8) สูงกว่าช่วงปกติ (~1.7) มาก

**วิธีทำ**: ถ่วงน้ำหนักแถวที่ค่าจริงเกิน 37.5 µg/m³ ด้วยน้ำหนัก 2/3/5 เท่า และแบบต่อเนื่อง วัดบน calibration

**หลักฐาน (เทียบไม่ถ่วงน้ำหนัก, LightGBM / XGBoost)**:

| น้ำหนัก | MAE รวม | ช่วงฝุ่นวิกฤต (>p90) |
|---|---|---|
| 2 เท่า | +2.2% / +2.0% | -6.9% / -4.8% |
| 3 เท่า | +4.6% / +4.3% | -9.2% / -7.7% |
| 5 เท่า | +8.3% / +7.7% | -12.0% / -9.7% |
| ต่อเนื่อง | +1.9% / +1.7% | -3.7% / -2.3% |

**สรุป**: เป็น**การแลกเปลี่ยน (trade-off)** ไม่ใช่ผลชนะฟรี — ช่วงวิกฤตแม่นขึ้น แต่ MAE รวมแย่ลงเกิน 1.7% ทุกค่า จึงไม่ใช้กับค่าพยากรณ์หลัก ✅ (ทดสอบและปิดประเด็น)

## ส่วนที่ 4: Retrain รุ่นใหม่ + ทดสอบซ้ำครบชุด

**วิธีทำ**: รวมสิ่งที่ผ่านเกณฑ์ (hyperparameter ที่จูนแล้ว + `nb_trend` 12 ชม.) เป็นโมเดลรุ่นใหม่ **ยืนยันบนชุดทดสอบครั้งเดียว** ก่อน retrain เต็ม (24 horizon × 3 quantile × 2 โมเดล) แล้วทดสอบซ้ำชุดเดียวกับรุ่นก่อนทุกมุม

**4.1 ผลยืนยันบนชุดทดสอบ (5 horizon ตัวแทน เทียบโมเดลรุ่นก่อน) — แยกผลของแต่ละส่วน**:

| โมเดล | รุ่นก่อน | จูน hyperparameter อย่างเดียว | จูน + `nb_trend` (รุ่นใหม่) |
|---|---|---|---|
| LightGBM MAE | 2.604 | 2.588 (-0.6%) | **2.538 (-2.6%)** |
| XGBoost MAE | 2.696 | 2.608 (-3.3%) | **2.542 (-5.7%)** |
| ช่วงฝุ่นวิกฤต (LGB / XGB) | 5.831 / 6.298 | — | **5.600 (-4.0%) / 5.723 (-9.1%)** |
| ช่วงฤดูฝุ่น (LGB / XGB) | 3.330 / 3.472 | — | **3.241 (-2.7%) / 3.259 (-6.1%)** |

- **ยิ่งพยากรณ์ไกลยิ่งได้ประโยชน์**: ที่ t+24 LightGBM ดีขึ้น 4.1%, XGBoost 7.6% (ที่ t+1 ดีขึ้นเพียง 0.8-1.4%)
- **ผลบนชุดทดสอบสอดคล้องกับที่เลือกบน calibration** (calibration: -2.5%/-2.9%, test: -2.6%/-5.7%) → ไม่มีสัญญาณ overfitting จากการลองหลายตัวเลือก

**4.2 ผลเต็ม (retrain ครบ 24 horizon, MAE เฉลี่ยทุก horizon)**: LightGBM 2.716 → **2.655** (-2.2%), XGBoost 2.810 → **2.655** (-5.5%), R² = 0.941 / 0.940

**4.3 ทดสอบซ้ำครบชุดเดียวกับรุ่นก่อน**:

| การทดสอบ | ผลบนรุ่นใหม่ | เทียบรุ่นก่อน |
|---|---|---|
| Backtest ฤดูฝุ่น (LGB) | MAE ปกติ 1.76 / ฤดูฝุ่น 3.39 / ช่วงวิกฤต 5.83 | ดีขึ้นทุกมุม; ความแตกต่างฤดูฝุ่นต่อปกติยังอยู่ (~+92%) |
| Ensemble vs Routing | simple average ชนะโมเดลเดี่ยวเพียง -0.30% | ช่องว่างสองโมเดลหายไป ข้อสรุปเดิม (คง Dynamic Routing) ไม่ขัดแย้ง |
| Zero-shot จังหวัดจริง (MAE, LGB) | นครพนม 4.78 / มหาสารคาม 2.92 / ร้อยเอ็ด 3.00 | นครพนมดีขึ้นชัด (5.02→4.78; XGB 5.33→4.79) |
| **Zero-shot coverage (นครพนม)** | **72.7% / 72.3%** | ⚠️ **แย่ลง** (เดิม 75.9% / 74.1%) |

**สรุป**: MAE ดีขึ้นทุกด้านและไม่มีจุดใดถอยหลังด้าน MAE — แต่ต้องรายงานตรงๆ ว่า **coverage ของนครพนมแย่ลง** แม้ค่าพยากรณ์แม่นขึ้น (โมเดลแม่นขึ้นกว่าเดิม แต่ช่วง P05-P95 แคบลงตามไปด้วยเมื่อ calibrate กับจังหวัดที่เทรน จึงครอบคลุมจังหวัดที่ผันผวนสูงได้น้อยลง)

## ส่วนที่ 5: Coverage — ทดลองเพิ่มเติมอีก 2 วิธี และข้อสรุปที่ควรยอมรับ

**ที่มา**: coverage ยังต่ำกว่าเป้า 90% (รวม ~88-89%, ช่วงฝุ่นวิกฤต ~84-87%) ทดลองแก้เพิ่มที่**หัวพยากรณ์ขอบช่วง (P05/P95)** ซึ่งยังใช้ค่า hyperparameter ที่จูนจากค่ากลาง (P50)

**วิธีทดลอง**: (1) ถ่วงน้ำหนักข้อมูลฝุ่นสูงเฉพาะหัว P95 (2) จูน hyperparameter แยกสำหรับหัว P05/P95 (เน้น regularize มากขึ้น) — วัดบน calibration แบ่ง 2 ท่อนตามเวลา (ท่อนแรกหา q_hat ท่อนหลังวัดผล)

**หลักฐาน (LightGBM / XGBoost)**:

| วิธี | Coverage รวม | ช่วงวิกฤต (>p90) | ความกว้างช่วง |
|---|---|---|---|
| ค่าปัจจุบัน | 86.3% / 85.3% | 84.5% / 83.2% | 9.8 / 9.5 |
| ถ่วงน้ำหนักหัว P95 | 86.6-87.0% / 85.5-86.1% | ไม่เปลี่ยน | กว้างขึ้น 3-15% |
| จูนหัว P05/P95 (regularize) | 89.1% / 89.0% | 88.0% / 87.6% | 11.3 / 11.3 (**กว้างขึ้น 15-20%**) |

**ตรวจว่าปรับปรุงจริงหรือแค่ช่วงกว้างขึ้น**: เทียบที่ความกว้างเท่ากัน — โมเดลปัจจุบันที่ขยายช่วงให้กว้างเท่ากันได้ coverage รวม **91.1%** (สูงกว่าโมเดลที่จูน 89.1%) และคะแนนช่วงพยากรณ์ (Winkler score) ดีกว่า → **coverage ที่สูงขึ้นมาจากช่วงกว้างขึ้นเท่านั้น ไม่ใช่คุณภาพช่วงพยากรณ์ที่ดีขึ้นจริง**

**สรุป**: ทั้ง 2 วิธี**ไม่ได้ปรับปรุงจริง** จึงไม่นำมาใช้ — ข้อสรุปที่ตรงไปตรงมา: coverage ราว 88-89% (ช่วงวิกฤต ~86% ด้วย calibration แบบแบ่งกลุ่มตามความรุนแรง) เป็น**ข้อจำกัดที่ยอมรับได้ของโมเดลนี้** ต่ำกว่าเป้า 90% เพียง 1-2 จุด และช่วงปกติได้ 90.2-90.5% ครบเป้าแล้ว การเพิ่ม coverage ทำได้โดยขยายช่วงพยากรณ์ แต่ต้องแลกกับช่วงที่กว้างขึ้น (ข้อมูลที่ใช้ตัดสินใจ ไม่ใช่ข้อบกพร่องที่ซ่อนอยู่) ⚠️ (ปิดการทดลอง ยอมรับเป็นข้อจำกัด)
