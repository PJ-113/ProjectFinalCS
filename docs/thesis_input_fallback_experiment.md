# ทางสำรองเมื่อแหล่งข้อมูลนำเข้าล่ม (OpenAQ / Open-Meteo)

> ที่มาของตัวเลข: `scripts/experiment_weather_fallback.py` → `models/experiment_weather_fallback_20260924_211247.csv` · โค้ดที่ใช้จริง: `app.py` (CHANGELOG 172)

## 1. ปัญหา
ระบบพยากรณ์ต้องการข้อมูลนำเข้าสด 2 แหล่งในทุกคำขอ: PM2.5 รายชั่วโมงจาก OpenAQ และสภาพอากาศปัจจุบันจาก Open-Meteo ก่อนงานนี้ไม่มีทางสำรองของทั้งสองแหล่ง: สภาพอากาศดึงไม่ได้ทำให้คำขอล้มเหลวทั้งคำขอ ส่วน PM2.5 ของจังหวัดเป้าหมายดึงไม่ได้ทำให้ตอบ 503 ทันที แม้ระบบเคยดึงข้อมูลสำเร็จเมื่อไม่กี่นาทีก่อน

## 2. แนวทาง
| ข้อมูล | ลำดับทางสำรอง | หลักฐานที่ใช้เลือก |
|---|---|---|
| สภาพอากาศ (Open-Meteo) | ค่าที่ดึงไว้ ≤ 10 นาที → ดึงสด → ค่าเก่า ≤ 2 ชม. → ค่าเฉลี่ยตามฤดูกาล (climatology) → ล้มเหลว | การทดลองในหัวข้อ 3 |
| PM2.5 จังหวัดเป้าหมาย (OpenAQ) | `/measurements` → `/hours` → ข้อมูลที่เก็บไว้ ≤ 6 ชม. → ล้มเหลว (503) | ตรวจความเทียบเท่าของ `/hours` (หัวข้อ 4) ; เกณฑ์ 6 ชม. ยืมจากกฎของจังหวัดเพื่อนบ้านที่ใช้อยู่แล้ว **ไม่ได้วัดแยก** |
| ทั้งสองแหล่ง | circuit breaker: ล้มเหลวต่อเนื่อง 5 ครั้งพัก 60 วินาที | ป้องกันงานรายชั่วโมงวน 20 จังหวัดใช้เวลาเกิน 1 ชม. เมื่อ API ล่มทั้งระบบ |

ไม่เลือก Air4Thai โดยตรง (เป็นต้นทางเดียวกับที่ OpenAQ รับต่อ ล่มพร้อมกัน และเคยวัดพบว่าค่าคนละสเกล — ต้อง calibrate ใหม่ 20 จังหวัดจากข้อมูลที่เก็บย้อนหลังได้เพียง ~2 เดือน) และไม่เลือกผู้ให้บริการอากาศรายอื่น (ยังไม่ได้ตรวจว่ามีครบ 6 ตัวแปรและสเกลเดียวกับข้อมูลเทรนหรือไม่)

## 3. การทดลอง: สภาพอากาศเก่า / ค่าเฉลี่ยตามฤดูกาลทำให้พยากรณ์เสียแค่ไหน
**วิธี.** ใช้โมเดล v3 ตัวเดิม (ไม่เทรนใหม่) เปลี่ยนเฉพาะ 7 feature สภาพอากาศ (temp, humidity, wind_speed, precipitation, wind_dir sin/cos, pressure) ของชุดข้อมูลเดียวกับที่ประเมินโมเดล แล้ววัด MAE ของ P50 เฉลี่ย 5 horizon (t+1, 6, 12, 18, 24) ทั้ง LightGBM และ XGBoost
- *ค่าเก่า k ชม.:* ใช้สภาพอากาศของจังหวัดเดียวกันเมื่อ k ชม. ก่อน (เท่ากับใช้ค่าที่ cache ไว้ตอนดึงสำเร็จครั้งสุดท้าย)
- *climatology:* ค่าเฉลี่ยของ (จังหวัด × เดือน × ชั่วโมง UTC) จากชุด train เท่านั้น
- ทุกสถานการณ์ประเมินบนแถวชุดเดียวกัน ตัดสินด้วย calib split แล้วยืนยันบน test split ครั้งเดียว (chronological ต่อจังหวัด: calib ส่วนใหญ่คือ ก.ย.–ม.ค., test คือ ก.พ.–มิ.ย.)

**เกณฑ์ที่ตั้งก่อนดูผล (ทั้งสองโมเดลต้องผ่านพร้อมกัน).**
- (A) ใช้ค่าเก่า k ชม. ได้ ถ้า MAE รวมเสียไม่เกิน +1.0%, ช่วงเดือน ก.พ.–เม.ย. (ฤดูฝุ่น) ไม่เกิน +1.5% และกลุ่ม >p90 ไม่เกิน +1.5% เทียบสภาพอากาศจริง
- (B) ใช้ climatology เป็นทางสุดท้ายได้ ถ้า MAE ต่ำกว่า Persistence ทุก horizon (ทั้งรวมและช่วงฤดูฝุ่น) — เพราะสิ่งที่ระบบจะตกไปใช้ถ้าไม่มี climatology คือ Persistence

**ผล (MAE เสียเพิ่มเทียบสภาพอากาศจริง, เฉลี่ย 5 horizon; ผ่านเกณฑ์ A เฉพาะแถวที่มีเครื่องหมาย ✓).**

| สถานการณ์ | calib LGB / XGB | test LGB / XGB | ผ่าน A |
|---|---|---|---|
| ค่าเก่า 1 ชม. | +0.40% / +0.42% | +0.36% / +0.41% | ✓ |
| ค่าเก่า 2 ชม. | +0.93% / +0.99% | +0.83% / +0.92% | ✓ |
| ค่าเก่า 3 ชม. | +1.54% / +1.64% | +1.32% / +1.46% | ✗ (calib ฤดูฝุ่น +2.5% / +2.8%) |
| ค่าเก่า 6 ชม. | +3.31% / +3.55% | +2.74% / +2.96% | ✗ |
| ค่าเก่า 12 ชม. | +5.85% / +6.29% | +4.72% / +4.88% | ✗ |
| ค่าเก่า 24 ชม. | +6.69% / +6.74% | +6.24% / +6.45% | ✗ |
| climatology | +4.70% / +4.61% | +3.05% / +3.53% | (ไม่ใช้เกณฑ์ A) |

**เกณฑ์ B — MAE ของ climatology ต่ำกว่า Persistence (ร้อยละที่ลดลง; ช่วงของ calib/test × LGB/XGB).** t+1: 17.6–20.5% · t+6: 12.8–14.9% · t+12: 11.3–11.6% · t+18: 8.0–9.2% · t+24: 5.5–5.9% → **ผ่านทั้งสองโมเดล ทั้ง calib และ test**

**ข้อสรุป.** ใช้สภาพอากาศเก่าได้ไม่เกิน 2 ชม. (`WEATHER_CACHE_MAX_AGE_H = 2`) เกินนั้นใช้ climatology ซึ่งยังดีกว่า Persistence ทุก horizon

**ข้อสังเกตนอกเกณฑ์ที่ตั้งไว้ (ไม่ใช้ตัดสิน).** ค่าเก่า 3–6 ชม. มี MAE รวมใกล้เคียงหรือดีกว่า climatology แต่ในกลุ่มฝุ่นสูง (>p90) บน calib climatology แย่กว่าค่าเก่ามาก (+12–17% เทียบ +3.6–3.8% ที่ 6 ชม.) การขยายเกณฑ์เกิน 2 ชม. จึงต้องตั้งเกณฑ์ใหม่แล้ววัดใหม่ ไม่ควรปรับหลังเห็นผล

## 4. การตรวจ `/hours` ของ OpenAQ เป็นทางสำรองของ `/measurements`
ยิงจริงเทียบ 19 สถานี × 72 ชม. (สถานีเลยไม่มีข้อมูลทั้งสอง endpoint): ทุกจุดที่ซ้อนกันมีค่าต่างเฉลี่ย 0.0000 รวม 9 สถานีที่ `/measurements` ติดป้ายเวลาเลื่อน 23 ชม. (ที่ `/hours` ป้ายเวลาถูกอยู่แล้ว จึงไม่ต้องบวก offset) ข้อแลกเปลี่ยนที่วัดพบ: `/hours` **ช้ากว่า `/measurements` ประมาณ 1 ชม.** (วัดที่นาที 24 ของชั่วโมง ครบ 19/19 สถานี) ดังนั้นเป็นทางสำรองเท่านั้น

## 5. ข้อจำกัด
1. **ไม่ได้วัด coverage ของช่วงความเชื่อมั่นเมื่อใช้ข้อมูลสำรอง** — q_hat ปรับด้วยข้อมูลสมบูรณ์ ช่วงอาจแคบไปเล็กน้อย (ผลต่อค่าพยากรณ์จุดเล็ก: ≤ 1% ที่ 2 ชม.)
2. climatology ที่ใช้งานจริงคำนวณจากสภาพอากาศครบทุกชั่วโมงของ 20 จังหวัด (ไม่ขึ้นกับช่องว่าง PM2.5) ต่างจากตัวที่ใช้ในการทดลอง (จากแถว train ที่มี PM2.5 บางช่องบางมาก เช่น จังหวัดเลยเดือน ต.ค. ไม่มีแถวเลย) จึงไม่ใช่ artifact เดียวกับที่ประเมิน — ผลของการทดลองใช้อ้างถึงแนวทาง ไม่ใช่ตัวเลขของไฟล์ที่ deploy
3. เกณฑ์ cache จังหวัดเป้าหมาย 6 ชม. ยังไม่ได้วัด
4. เมื่อ OpenAQ ล่ม **ทั้งระบบ** จังหวัดเพื่อนบ้านค้างที่เวลาเดียวกัน การเติมค่าสถานีเงียบ (H-lite) จึงไม่ทำงาน (ต้องใช้ข้อมูลเพื่อนบ้านหลังเวลาที่สถานีเงียบ) ระบบตอบจากข้อมูลที่เก็บไว้พร้อมป้ายข้อมูลเก่า ทางสำรองนี้ช่วยเฉพาะปัญหาเฉพาะ endpoint/สถานีเดียว
5. `/hours` ช้ากว่า ~1 ชม. เมื่อใช้เป็นทางสำรองอาจทำให้ k ที่วัดได้เพิ่ม ~1 (มีผลกับ `IMPUTATION_MIN_K`)
6. ผลการทดลองอิงข้อมูลย้อนหลัง 2024-01 ถึง 2026-07 ยังไม่มีการทดสอบตอนแหล่งข้อมูลล่มจริงใน production
